# Reassign All QR Hilang - 10 November 2026

Tombol **Reassign All QR Hilang** ditambahkan tepat setelah **Generate All QR Code** pada katalog, termasuk tampilan embedded Master Opname. Setelah konfirmasi singkat, browser memproses10baris katalog aktif per request, menampilkan dipulihkan/dilewati/gagal, lalu memuat ulang tabel dan membersihkan pilihan cetak lama. Kedua tombol batch dinonaktifkan selama proses untuk mencegah klik ganda/dua batch dari halaman yang sama.

Route POST admin/stockopname/master_barang/reassign-missing-qrcode -> C_Stockopname::ajax_reassign_missing_catalog_qrcode -> create_catalog_qrcode -> M_Catalog_qr_issue::issue dengan missingOnly=true. Guard admin dashboard dan token sesi/CSRF mengikuti pola existing. Endpoint mengambil kandidat dari katalog aktif di server, bukan daftar ID/path dari client. QR belum tercatat, file masih ada, item tanpa master lokal dan histori yang tidak menjadi referensi aktif dilewati. Tidak membuat master atau penerbitan pertama secara otomatis.

Offset diterapkan pada seluruh daftar referensi, bukan daftar missing yang menyusut setelah diperbaiki. Fingerprint mode/batch/rows diberikan request pertama dan wajib cocok pada request berikutnya; jika katalog berubah, batch dihentikan dengan pesan untuk menjalankan ulang. Perbaikan parsial yang sudah sukses tidak dibatalkan; menjalankan ulang melewati file yang telah pulih.

M_Catalog_qr_issue menambahkan opsi missingOnly defaultfalse agar single Resign existing tetap berfungsi. Pada mode baru, setelah lock KIUBR dan row lock diperoleh, stat cache file dibersihkan dan keberadaan record/file diperiksa ulang. Record tidak ada atau file kembali tersedia: skipped tanpa generator, perubahan path atau audit penerbitan baru. Untuk missing yang sah, expected_file, referensi aktif dan transaksi existing tetap divalidasi. Aset dibuat lokal dengan nama baru; payload MB|id|tanggal tetap. Audit memakai operation=resign dan alasan server 'Reassign massal: file QR hilang', beserta pelaku, UTC dan aset lama/baru. Error satu item dicatat di laporan dan item berikutnya tetap diproses. Transaksi atomik per QR, bukan seluruh batch.

Berkas berubah: application/config/routes.php; application/controllers/admin/C_Stockopname.php; application/models/admin/M_Catalog_qr_issue.php; application/views/content/admin/stockopname_master_barang_catalog.php; tests/stockopname_zahir_snapshot_test.php. Perubahan pengguna yang sudah ada dipertahankan.

Uji database terpisah lulus untuk sehat/unissued dilewati tanpa mutasi/audit, missing dipulihkan, batas10dan halaman12baris tidak melompati item, rerun tidak menggandakan issue, perubahan katalog ditolak, token salah ditolak, payload tetap, actor/reason tercatat dan QR histori inactive tidak dipulihkan. Suite lokal/testing dan simulasi production lulus; regression input/scan, PHP lint dan git diff --check juga diperiksa. Tidak menjalankan mass reassign pada database aplikasi atau file QR pengguna. UAT browser, progres batch, putus jaringan dan cetak fisik masih perlu dilakukan.
