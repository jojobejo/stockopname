# Penggunaan impor snapshot Zahir

1. Administrator memasang migration pada lingkungan yang dipilih setelah backup/audit skema; development ini belum memigrasi database aplikasi. Periksa PHP BCMath, batas upload 5 MiB, post 8 MiB, memory 512M, timeout 120 detik dan TEMP privat di luar document root. Tidak memerlukan koneksi Zahir untuk imported.
2. Exporter menyediakan JSON v1 atau CSV UTF-8 header kode_barang,nama_barang,expired_date,qty_lot,p,l,t. Sertakan kode asli sebelum grouping, qty nol/negatif, seluruh cakupan; jangan memakai file yang gagal/parsial. Kontrak bersama dan contoh sintetis: docs/contracts/zahir-snapshot-v1.md dan contoh .json/.csv. Jangan upload SQL dump.
3. Untuk CSV ambil metadata dari laporan exporter: schema_version=1, source_system=ZahirDigital, source_instance stabil, scope stabil, UUID snapshot, exported_at dengan zona waktu, snapshot_type=full, row_count dan pernyataan complete. Jangan mengarang timestamp atau mengambil UUID hanya dari nama file. CSV lampiran memiliki 2065 rows valid; identitas full dan waktu sumber tetap wajib dipastikan exporter. JSON membawa metadata di dalam file; formulir metadata tidak menimpanya.
4. Masuk admin dashboard, buka tautan **Impor Snapshot Zahir** pada Master Barang lokal/katalog, atau admin/stockopname/zahir-snapshot. Ini menu berbeda dari impor master lokal dan impor Master Opname.
5. Upload dan dry-run. Periksa jumlah sumber/valid/error/duplikat, barang baru, existing, before/after nama/P/L/T/dimensi, konflik identitas dan antar-LOT, missing grain, kelompok aktif/nonaktif, checksum, timestamp, cakupan. Laporan kesalahan menampilkan nomor row data (header CSV tidak dihitung). Qty referensi tidak menjadi hasil fisik. Baris dengan tanggal null/ukuran hilang atau pecahan menahan seluruh aktivasi; minta perbaikan sumber atau kebijakan bisnis formal, jangan isi 0 sembarangan.
6. Jika bersih, konfirmasi seluruh perubahan kandidat master dan aktivasi snapshot tersebut. Konfirmasi berlaku satu jam dan hanya untuk file/master/snapshot yang dipreview. Jika master berubah, ulangi dry-run. Jika impor lain memegang lock, tunggu lalu ulangi. Upload baru membatalkan preview lama. Snapshot lama tetap aktif sampai commit sukses.
7. Pengiriman ulang identik saat masih aktif menghasilkan no-op; ID sama dengan bytes/metadata berbeda ditolak. Waktu sumber sama atau lebih lama ditolak; full kosong juga ditolak. Pemulihan historis memakai tindakan terpisah di bawah halaman, bukan memodifikasi tanggal file.
8. Atur environment server ZAHIR_CATALOG_MODE=imported dan ZAHIR_SOURCE_INSTANCE/ZAHIR_SCOPE sesuai pasangan metadata. Default konfigurasi direct; pergantian mode dilakukan pengelola aplikasi, bukan tombol refresh. Ubah konfigurasi melalui proses rilis lalu restart/reload worker bila diperlukan. Imported tidak fallback ke jaringan internal/cache HTML. Jika belum ada snapshot atau migration belum tersedia, halaman memberi petunjuk/error, bukan mengambil IP lokal.
9. Banner status menampilkan waktu sumber, waktu impor UTC dan usia. Refresh hanya membaca snapshot tersimpan; tidak membuktikan data sumber baru diterima. Perubahan katalog terbaru memerlukan ekspor baru lengkap dan impor baru. Barang hilang/qty kelompok tidak positif berhenti tampil sebagai referensi aktif; master/QR/histori tetap ada. Jika representative atau expired berubah, QR lama tetap tersimpan namun mungkin tidak lagi valid untuk scan; generate QR untuk pasangan aktif melalui menu katalog dan verifikasi hasilnya.
10. Pemulihan: backup dulu, periksa snapshot aktif dan cakupan, lalu pilih aksi **Pulihkan snapshot sebelumnya** yang terpisah dan tercatat audit. Existing kandidat dikembalikan hanya jika belum diedit setelah impor; ID/metadata lain/master baru/QR/histori tetap. Jika konflik atau tidak ada predecessor, hentikan recovery otomatis dan minta rekonsiliasi admin berdasarkan before/after dan backup. Jangan hapus histori atau memundurkan watermark dengan edit SQL manual.
